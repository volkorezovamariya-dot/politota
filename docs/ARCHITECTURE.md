# Архитектурный контур Politota

## Слои системы

### 1. Sources

Открытые источники: официальная статистика, реестры бизнеса, государственные закупки, цены, локальные медиа, вакансии, транспортные и инфраструктурные сообщения.

### 2. Ingestion

Каждый коннектор сохраняет исходный материал без изменения, время получения, URL/идентификатор источника и технический статус загрузки.

### 3. Normalization

Сырые записи преобразуются в единую модель:

- `country` и более точная география;
- `observed_at` и `published_at`;
- `category`;
- числовое значение или наблюдаемый факт;
- источник и метод получения;
- качество и полнота данных.

### 4. Signal engine

Система сравнивает наблюдение с исторической нормой, соседними регионами и связанными индикаторами. Результат — сигнал с оценкой силы, уверенности и направления.

### 5. Interpretation

Факт, аналитическая интерпретация и прогноз хранятся отдельно. Прогноз обязан содержать вероятность, горизонт, аргументы «за» и условия опровержения.

### 6. Presentation

Дашборд показывает не только итоговый индекс, но и вклад сигналов, источник, давность и уровень неопределённости.

## Минимальная сущность Signal

```json
{
  "id": "sig-001",
  "country": "AR",
  "category": "economy",
  "title": "...",
  "observed_at": "2026-07-25",
  "source": "...",
  "confidence": 84,
  "impact": 78,
  "direction": "negative"
}
```

## Нефункциональные требования

- воспроизводимость расчётов;
- версионирование формул и данных;
- сохранение первичного источника;
- явная маркировка синтетических и неполных данных;
- отсутствие автоматических политических утверждений без доказательной цепочки;
- возможность пересчитать историю после изменения модели.

## Технологический путь

Sprint 0 использует HTML/CSS/JavaScript без сборщика. После подтверждения продуктовой модели целевой контур может включать Python для ingestion и аналитики, PostgreSQL для хранения, FastAPI для API и отдельный web-клиент.
